# 项目需求文档

## 目标

构建一个本地管理系统后端与 Web 管理台，为独立的 Android App 自动化项目提供账号管理、任务管理、结果查询和风控支撑。

当前业务目标调整为：

- App 端负责执行小红书操作。
- Web 页面只做管理系统，不直接承担小红书业务执行。
- 发帖、关键词搜索采集、博主数据监控都在 App 端实现。
- 本项目负责接口、任务编排、Cookie 管理、结果存储和风控约束。

## 目标用户

- 品牌运营团队
- 内部运营执行人员
- App 自动化项目的后端对接方

## 系统边界

| 模块 | 职责 |
|---|---|
| App 端 | 登录小红书、执行发帖、执行搜索采集、采集账号数据、回传结果 |
| Web 管理系统 | 管理账号、Cookie、任务、采集结果、风控配置和状态查看 |
| 本项目后端 | 提供接口、存储任务与结果、控制 Cookie 使用策略、做基础风控 |

App 端会在另一个独立项目中实现，本仓库不负责 Android 自动化细节。

## 功能范围

### 账号与 Cookie 管理

- 支持维护主账号 Cookie 和小号 Cookie。
- 主账号 Cookie 用于发帖。
- 非发帖类请求默认优先使用小号 Cookie。
- 小号 Cookie 需要支持录入、删除、启用、停用、备注和有效性校验。
- 小号 Cookie 需要按池化方式管理，形成 Cookie 池。
- Cookie 池需要支持轮询分配，尽量分散搜索和数据采集请求。
- 需要记录 Cookie 最近使用时间、最近校验时间、最近失败时间、连续失败次数。
- 连续失败、失效或触发疑似风控时，需要自动停用并进入冷却。
- Web 页面不展示完整 Cookie。

### App 登录支持

- App 端通过手机号和短信验证码完成登录。
- 登录成功后，App 端将主 Cookie 提交给本项目后端保存。
- 后端需要提供主 Cookie 更新和有效性校验能力。
- 当前不要求在本项目内实现短信通道或验证码页面。

### 发帖任务管理

- Web 管理系统支持创建待发帖任务。
- 发帖任务字段至少包含标题、正文、话题、媒体列表、计划时间、目标账号。
- 发帖任务默认需要人工审核通过后，App 才可拉取执行。
- App 端可从后台拉取待发帖列表。
- App 端发帖完成后回传执行结果。
- 后台支持查看待发帖列表、执行中状态、已发帖列表、失败列表。
- 后台保留发帖记录、失败原因和最近执行时间。
- 发帖使用主账号 Cookie。
- 同一主账号发帖必须串行执行，不允许并发发帖。
- 一个主账号默认只绑定一个 App 执行设备；如后续放开，需要额外的排它控制。

### 关键词搜索采集任务

- Web 管理系统支持创建关键词采集任务。
- 任务字段至少包含关键词、执行频率、单次采集数量、排序方式、时间范围、启停状态。
- App 端可拉取需要执行的关键词任务。
- App 端执行搜索、滚动和摘要提取后回传结果。
- 后台支持查看任务列表和已采集数据。
- 搜索结果默认保存摘要信息，不要求默认抓取全部详情。
- 搜索和采集默认使用小号 Cookie 池轮询。
- 小号 Cookie 池建议按品牌、项目或账号组隔离，避免不同业务互相污染。
- 搜索采集默认不保存原始截图；如后续需要截图取证，必须单独配置并限制频率与存储量。

### 博主与账号数据监控

- App 端支持查询当前账号自己的关键数据。
- 采集范围至少包括：
  - 点赞数
  - 发帖数
  - 每个帖子的详情数据
- 后端支持保存账号监控快照。
- 后台支持查看历史快照和最近一次采集结果。
- 数据采集默认优先使用小号 Cookie；如果必须使用主账号，需要明确标记并控制频率。
- 账号监控默认最低执行频率不高于每 6 小时一次；如需更高频率，必须单独评估风控风险。

### 管理系统页面

- Web 页面定位为管理后台。
- 管理后台至少覆盖：
  - 账号管理
  - 主 Cookie 管理
  - 小号 Cookie 池管理
  - 发帖任务管理
  - 已发帖记录查看
  - 关键词采集任务管理
  - 已采集结果查看
  - 账号数据监控结果查看
  - 基础运行状态和风控状态查看
  - 人工审核与处理状态查看
  - 操作日志与审计日志查看

### 任务调度与执行约束

- App 与后端之间必须使用明确的设备标识，至少包括 `device_id`、`app_instance_id`、`app_version`、`device_name`。
- 后端需要记录 App 心跳时间，用于判断设备在线状态。
- 同一设备默认同一时刻只执行一个任务，不并发执行发帖与采集。
- 任务被 App 领取后，如果在规定时间内未回传结果，需要自动回收。
- 任务领取超时建议默认 15 分钟。
- 失败任务默认仅允许有限重试，建议最多 1 到 2 次。
- 定时任务错过计划执行时间时，默认允许补跑一次，不做无限追赶。

### 结果模型与幂等要求

- App 回传结果必须支持幂等。
- 每次回传至少包含 `task_id`、`result_id`、`device_id`。
- 后端应以 `task_id + result_id` 作为幂等键，避免重复入库。
- 搜索与监控回传需要支持部分成功，不要求单次必须全量成功。
- 采集结果与账号监控结果需要保留结构化字段，避免只存原始文本。

建议的搜索结果核心字段：

| 字段 | 说明 |
|---|---|
| `post_id` | 帖子 ID |
| `post_url` | 帖子链接 |
| `title` | 标题 |
| `content_preview` | 摘要 |
| `like_count` | 点赞数 |
| `comment_count` | 评论数 |
| `collect_count` | 收藏数 |
| `publish_time` | 发布时间 |
| `author_name` | 作者名 |
| `author_id` | 作者 ID |

建议的账号快照核心字段：

| 字段 | 说明 |
|---|---|
| `account_id` | 主账号 ID |
| `nickname` | 账号昵称 |
| `follower_count` | 粉丝数 |
| `liked_total` | 获赞总数 |
| `post_total` | 发帖总数 |
| `collected_total` | 被收藏总数，可选 |

### 素材与媒体约束

- 第一版发帖任务默认使用可访问的媒体 URL，由 App 自行下载。
- 后端需要保存媒体 URL、媒体类型、顺序和可选封面图 URL。
- 需要定义图片、视频数量和大小上限，由 App 端执行前做二次校验。
- 媒体 URL 失效、下载失败或格式不支持时，App 必须回传明确错误原因。

### 人工处理与审计

- 采集结果和任务记录需要支持人工备注。
- 结果列表需要支持人工标记无效、隐藏或驳回。
- 后端需要保存任务领取日志、Cookie 分配日志、风控事件日志、结果回传日志和人工操作日志。

### 风控策略

所有需求必须遵守根目录 [RISK_CONTROL.md](../RISK_CONTROL.md)。

除了发帖必须使用主 Cookie，其他接口默认按“小号优先、池化轮询、失败冷却、按需采集”的原则设计。

### 国际化

- Web 页面提供中英文切换入口。
- 第一版优先覆盖管理系统导航、账号管理、任务管理和结果查看页面。

### UI 与响应式

- 前端使用 Tailwind CSS 和 shadcn/ui 配置体系。
- 页面重点是桌面端管理后台体验。
- 移动端可访问，但不再以移动端操作页为主要设计目标。

## 暂不包含

- 私信监控。
- 私信自动回复。
- 本仓库内实现 Android App 自动化。
- 本仓库内实现手机号短信发送能力。
- 公网部署和多用户权限系统。
- 验证码绕过、高频并发、批量账号并发刷接口。
- 未经风控约束的自动详情全量抓取。
