# 项目需求文档

## 目标

构建一个本地管理系统后端与 Web 管理台，为独立的 Android App 自动化项目提供账号管理、任务管理、结果查询和风控支撑。

当前业务目标调整为：

- App 端负责执行小红书操作。
- Web 页面只做管理系统，不直接承担小红书业务执行。
- 后台创建发帖任务，App 拉取后在本机执行发布并回传结果。
- App 创建关键词搜索任务，并查看帖子数量、帖子列表和帖子详情。
- App 查看当前登录账号的个人信息。
- 本项目负责接口、发帖任务存储、搜索任务与结果存储、结果查询和风控约束。

## 目标用户

- 品牌运营团队
- 内部运营执行人员
- App 自动化项目的后端对接方

## 系统边界

| 模块 | 职责 |
|---|---|
| App 端 | 手机号验证码登录、持有 Cookie、拉取并执行发帖任务、创建关键词搜索任务、查看搜索结果与账号信息、回传发帖结果 |
| Web 管理系统 | 查看主账号状态、创建发帖任务、查看发帖记录、查看搜索任务与结果、维护小号池与设备状态 |
| 本项目后端 | 提供接口、存储发帖任务、执行关键词任务与账号监控任务、存储搜索任务与结果、记录回传结果、提供查询接口和基础风控约束 |

App 端会在另一个独立项目中实现，本仓库不负责 Android 自动化细节。

## 功能范围

### 账号与 Cookie 管理

- App 端通过手机号和短信验证码登录主账号，并在本地持有 Cookie。
- 主账号 Cookie 用于 App 端发帖、关键词搜索和账号信息查看。
- 后端可保存主账号 Cookie 或 Cookie 状态，用于状态展示、有效性校验和故障排查；如果后端不代发，可不依赖完整 Cookie 执行业务。
- 需要记录 Cookie 最近校验时间、最近失败时间、连续失败次数和冷却状态。
- 连续失败、失效或触发疑似风控时，需要进入冷却并停止继续请求。
- Web 页面不展示完整 Cookie。
- Web 小号池支持三种录入方式：直接粘贴 Cookie、手机号验证码登录、扫码登录。
- 小号池当前不区分分组和用途标签，统一按可用状态轮询使用；请求执行中展示为忙碌，空闲时可再次分配。
- Web 端主账号和小号账号都需要提供显式的 Cookie 校验入口，并展示校验后的状态变化。
- 主账号和小号账号的校验需要真实请求小红书接口验证登录态，不只做本地格式校验。
- Web 端不提供主账号新增入口；主账号新增、登录和 Cookie 更新只在 Android 端处理。

### App 登录支持

- App 端通过手机号和短信验证码完成登录。
- 登录成功后，App 端本地保存主账号 Cookie。
- App 可把主 Cookie 或脱敏后的账号状态提交给本项目后端保存。
- 后端需要提供主 Cookie 更新和有效性校验能力，但不把“同步 Cookie”设计成独立任务流。
- 当前不要求在本项目内实现短信通道或验证码页面。

### 发帖任务管理

- Web 管理系统支持创建待发帖任务。
- 发帖任务字段至少包含标题、正文、话题、媒体列表、计划时间、目标账号。
- 当前 Web 端创建发帖任务后默认直接进入待发布，不再提供通过/拒绝审核操作。
- App 端可从后台拉取待发帖列表。
- App 端发帖完成后回传执行结果。
- 后台支持查看待发布、发布成功、发布失败三类状态，并可在失败后重新入队。
- 后台保留发帖记录、失败原因和最近执行时间。
- 发帖使用主账号 Cookie。
- 同一主账号发帖必须串行执行，不允许并发发帖。
- 一个主账号默认只绑定一个 App 执行设备；如后续放开，需要额外的排它控制。

### 关键词搜索采集任务

- App 支持创建关键词搜索任务。
- 任务字段至少包含关键词、执行频率、单次采集数量、排序方式、时间范围、启停状态。
- 关键词任务由本项目后端按计划执行，App 端只负责创建任务和查看结果。
- 后台支持保存任务列表、帖子数量、帖子列表和帖子详情。
- App 端可查看搜索任务列表、任务详情、帖子数量、帖子列表和单条帖子详情。
- 搜索结果默认保存摘要信息，不要求默认抓取全部详情。
- 搜索默认使用 App 当前登录账号 Cookie；如果后续引入小号池，必须明确账号用途并单独限速。
- 搜索采集默认不保存原始截图；如后续需要截图取证，必须单独配置并限制频率与存储量。

### 博主与账号数据监控

- App 端支持查询当前登录账号自己的关键数据。
- 采集范围至少包括：
  - 点赞数
  - 发帖数
  - 每个帖子的详情数据
- 账号监控任务由本项目后端按计划执行，并保存账号监控快照。
- 后台支持查看历史快照和最近一次采集结果。
- 当前登录账号个人信息由 App 使用本地登录态低频查询。
- 账号监控默认最低执行频率不高于每 6 小时一次；如需更高频率，必须单独评估风控风险。

### 管理系统页面

- Web 页面定位为管理后台。
- 管理后台至少覆盖：
  - 账号管理
  - 主账号状态查看
  - 发帖任务管理
  - 已发帖记录查看
  - 关键词搜索任务查看
  - 搜索帖子数量、列表和详情查看
  - 账号数据监控结果查看
  - 基础运行状态和风控状态查看
  - 操作日志与审计日志查看

### 任务调度与执行约束

- App 与后端之间建议带 `device_id`、`app_instance_id`，用于任务领取和结果幂等排查。
- 不要求 App 上报独立心跳；拉取任务、创建任务和回传结果本身可作为最近活动记录。
- 同一设备默认同一时刻只执行一个发帖任务；关键词任务和账号监控任务由后端串行调度执行。
- 任务被 App 领取后，如果在规定时间内未回传结果，需要自动回收。
- 任务领取超时建议默认 15 分钟。
- 失败任务默认仅允许有限重试，建议最多 1 到 2 次。
- 定时任务错过计划执行时间时，默认允许补跑一次，不做无限追赶。

### 结果模型与幂等要求

- App 回传结果必须支持幂等。
- 每次回传至少包含 `task_id`、`result_id`、`device_id`。
- 后端应以 `task_id + result_id` 作为幂等键，避免重复入库。
- 搜索与监控回传需要支持部分成功，不要求单次必须全量成功。
- 采集结果与账号监控结果需要保留结构化字段，避免只存原始文本。

建议的搜索结果核心字段：

| 字段 | 说明 |
|---|---|
| `post_id` | 帖子 ID |
| `post_url` | 帖子链接 |
| `title` | 标题 |
| `content_preview` | 摘要 |
| `like_count` | 点赞数 |
| `comment_count` | 评论数 |
| `collect_count` | 收藏数 |
| `publish_time` | 发布时间 |
| `author_name` | 作者名 |
| `author_id` | 作者 ID |

建议的账号快照核心字段：

| 字段 | 说明 |
|---|---|
| `account_id` | 主账号 ID |
| `nickname` | 账号昵称 |
| `follower_count` | 粉丝数 |
| `liked_total` | 获赞总数 |
| `post_total` | 发帖总数 |
| `collected_total` | 被收藏总数，可选 |

### 素材与媒体约束

- 第一版发帖任务默认使用可访问的媒体 URL，由 App 自行下载。
- 后端需要保存媒体 URL、媒体类型、顺序和可选封面图 URL。
- 需要定义图片、视频数量和大小上限，由 App 端执行前做二次校验。
- 媒体 URL 失效、下载失败或格式不支持时，App 必须回传明确错误原因。

### 人工处理与审计

- 采集结果和任务记录需要支持人工备注。
- 结果列表需要支持人工标记无效、隐藏或驳回。
- 后端需要保存任务领取日志、Cookie 分配日志、风控事件日志、结果回传日志和人工操作日志。

### 风控策略

所有需求必须遵守根目录 [RISK_CONTROL.md](../RISK_CONTROL.md)。

App 侧触发小红书业务接口时，默认按“账号级串行、失败冷却、Cookie 复用、按需采集”的原则设计。搜索和详情查看不得默认全量批量请求。

### 国际化

- Web 页面提供中英文切换入口。
- 第一版优先覆盖管理系统导航、账号管理、任务管理和结果查看页面。

### UI 与响应式

- 前端使用 Tailwind CSS 和 shadcn/ui 配置体系。
- 页面重点是桌面端管理后台体验。
- 移动端可访问，但不再以移动端操作页为主要设计目标。

## 暂不包含

- 私信监控。
- 私信自动回复。
- 本仓库内实现 Android App 自动化。
- 本仓库内实现手机号短信发送能力。
- 公网部署和多用户权限系统。
- 验证码绕过、高频并发、批量账号并发刷接口。
- 未经风控约束的自动详情全量抓取。
