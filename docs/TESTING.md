# 自动化测试

## 测试目标

测试体系用于保护“Web 管理系统 + App 对接后端”的基础能力，避免后续开发破坏任务接口、Cookie 管理和风控约束。

## 覆盖范围

- 后端健康检查。
- 主账号 Cookie 和小号 Cookie 的录入、脱敏展示和有效性校验。
- Web 小号池的直接 Cookie、短信验证码登录、扫码登录三种录入方式。
- Cookie 池轮询分配、停用、冷却和恢复。
- App 上传主 Cookie 接口。
- App 手机号验证码发送和验证码登录接口。
- 发帖任务创建、列表、状态流转、结果回传。
- 已发帖列表查询。
- App 创建关键词搜索任务、查看任务列表、查看任务详情和帖子数量。
- 后端执行关键词任务、搜索结果入库和手动触发执行。
- 采集结果按任务和笔记去重。
- 后端执行账号监控任务、监控快照入库和查询。
- 调度器时间回归测试：历史无时区 `last_check_at`、`last_run_at` 不得导致任务执行崩溃。
- 风控相关边界校验：串行、限速、失败冷却。
- 前端 TypeScript 和 Vite 构建。

## 当前测试缺口

- 当前很多测试仍围绕历史 Web 直接执行路径，后续需要逐步迁移。
- 尚未接入浏览器端自动化测试，暂时不能覆盖管理系统表单交互和错误提示渲染。
- 后续需要补 Playwright 冒烟测试，至少覆盖账号管理、发帖任务管理、App 关键词任务查看和搜索结果详情。

## 运行方式

后端测试：

```bash
python -m pytest
```

前端构建：

```bash
cd frontend
npm run build
```

一键检查：

```bash
sh scripts/check.sh
```

查看后端日志：

```bash
tail -f logs/backend.log
```

## 约定

- 测试不能真实请求小红书。
- 测试不能真实请求第三方发布服务。
- 测试不能使用真实 Cookie 或 API Key。
- App 对接相关测试必须使用 mock 请求和本地假数据。
- 新增后端接口时，优先补对应 TestClient 测试。
- 新增前端关键流程时，至少保证 `npm run build` 通过；复杂交互后续补 Vitest 或 Playwright。
