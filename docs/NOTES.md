# 注意事项

## 安全

- Cookie 明文存储在 `datas/accounts.json`。
- 第三方发布 API Key 明文存储在 `datas/operations.json`。
- 不要提交 `datas/accounts.json`、`datas/operations.json`、`.env`。
- 不建议公网部署。
- 前端不会展示完整 Cookie。
- 后续需要区分主账号 Cookie 和小号 Cookie，不能混用。
- 主账号 Cookie 仅用于发帖及少量必须使用主账号的动作。
- 小号 Cookie 主要用于搜索、数据采集和非发帖类读取接口。
- PC 端扫码登录生成的临时 Cookie 只保存在后端内存会话中，登录成功后才写入 `datas/accounts.json`。
- 手动 Cookie 保存时如果账号名留空，后端会尝试用该 Cookie 读取昵称；读取失败时保存为“手动账号”。

## 风控

- 默认按需加载详情，不自动批量拉取。
- 同一账号请求串行，并带随机间隔。
- 连续失败后进入冷却。
- 小号 Cookie 需要池化管理，避免固定单号连续承担搜索和采集请求。
- 小号 Cookie 需要轮询分配，并记录最近使用时间和失败次数。
- 小号 Cookie 连续失败、失效或疑似触发风控时，需要自动停用并进入冷却。
- 除发帖外，其它任务默认优先走小号 Cookie。
- 同一设备默认一次只执行一个任务，避免频繁前后台切换增加异常行为。
- 发帖任务默认先人工审核，再允许 App 领取。
- 扫码登录状态由前端低频轮询，二维码过期或登录成功后立即停止。
- 新增任何批量功能前，必须先设计暂停、取消、限速和失败处理。
- 评论自动回复当前只支持手动执行单条规则，不做后台常驻轮询。
- 评论自动回复依赖 PC Web 评论接口，发送参数按当前仓库静态脚本线索实现，后续如接口字段变化需重新校验。
- 未读评论工作台依赖评论提醒消息流，消息字段结构如平台返回变动，需要同步调整解析逻辑。

## 运行

- 开发模式前端端口是 `5173`。
- Docker 模式统一访问后端端口 `8000`，FastAPI 会托管前端构建产物。
- Docker 运行镜像必须包含 Node.js 和根目录 npm 依赖，否则 `PyExecJS` 无法执行签名 JS，扫码登录和业务接口签名会失败。当前签名 JS 至少依赖 `crypto-js`，部分历史签名文件依赖 `jsdom`。
- 如果本机 8000 端口被占用，可以修改 `docker-compose.yml` 的端口映射。

## 当前限制

- 当前仓库代码仍以历史 Web 直接执行路径为主，和新的“App 执行、Web 管理”方向还未完全对齐。
- 关键词监控自动定时调度尚未实现。
- 账号分析目前仍是基础快照能力，趋势图和对比分析尚未实现。
- 不包含私信。
- App 自动化将在独立项目实现，本仓库只提供接口和管理后台。
- App 端手机号短信登录流程尚未在本仓库内落地。
- 小号 Cookie 池、轮询分配和冷却恢复机制尚未实现。
- 设备心跳、任务领取超时回收、结果幂等处理尚未实现。
- 已有发布页、搜索页和历史评论能力后续需要按新方向重构或下线。
- 页面中英文切换第一版覆盖主要导航，历史页面文案仍需继续补齐。

## 开发约定

- 后端接口都放在 `server/main.py`。
- 本地运营数据读写放在 `server/operation_store.py`。
- 账号数据读写放在 `server/account_store.py`。
- 前端主页面目前集中在 `frontend/src/main.tsx`。
- 前端视觉样式使用 Tailwind CSS，shadcn/ui 配置在 `frontend/components.json`，基础主题在 `frontend/tailwind.config.js` 和 `frontend/src/styles.css`。
- 风控策略维护在 `RISK_CONTROL.md`。
- 测试文档维护在 `docs/TESTING.md`。
- 后续需求或行为变化需要同步更新相关文档和测试。
